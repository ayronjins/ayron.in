Home Lab / Infrastructure and operations

The systems layer behind the work.

The Home Lab is where infrastructure concepts become operating practice. It brings together Linux administration, Proxmox virtualization, Docker services, Nginx at the web edge, DNS, storage, systemd service management, monitoring and backups. The important part is not the list of products; it is being able to explain the request path and identify which boundary failed.

The same thinking supports the public tools: validate an input, constrain a capability, observe the result and make the next decision from evidence. The homelab and networking case study records the operating environment and the storage expansion incident in more detail.

STACK / 07

Infrastructure is really a relationship between layers. Virtual machines handle separation. Linux gives you the operating surface underneath everything. Containers package the services, Nginx routes the public requests, and monitoring is what actually surfaces a failure before you have to go looking for it.

Networking then connects those layers through DNS, routes, TLS and controlled exposure. The result is a practical environment for building, breaking and repairing systems.

AI systems / KHS AI

Make intelligence operate inside a boundary.

The AI work here is about more than generating text. KHS AI is really an exploration of how a model reasons about a goal, works with the tools it's explicitly given, interacts with software, and (this is the part that matters) knows when to stop or recover once the outcome looks uncertain.

The surrounding system is what actually determines whether an agent is useful: permissions, state tracking, APIs, local model runtimes, user control, verification. None of that shows up in a demo, but all of it decides whether the thing works. Read the KHS AI case study for the architecture, limits and testing questions, or open the broader AI and development page for the surrounding vocabulary.
